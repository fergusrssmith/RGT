# Handover: RGT-Est low-frequency-model (LFM) workflow

Handover from an earlier Claude session, so work can continue with direct RokDoc integration (via the RokDoc Python API) instead of exporting and uploading files by hand.

**Repository:** https://github.com/fergusrssmith/RGT (a fork of `douyimin/RGT-Est`). Everything described here is on `main`.

---

## 1. Goal

A **semi-automated low-frequency model (LFM) workflow for seismic inversion in RokDoc**:

- **Inputs:** a seismic volume, a few key horizons, an interval-velocity model, and impedance logs at wells (with their positions).
- **Process:** build a relative geologic time (RGT) volume from the seismic, then interpolate the wells' impedance **along RGT layers** (not flat time) on top of a velocity-derived background.
- **Outputs:** an LFM SEG-Y, plus RGT volumes, horizons and QC, back into RokDoc.
- **Longer term:** training and optimisation decisions (e.g. the LFM frequency cut-off from spectral analysis of the seismic) derived inside the workflow. A human approves at checkpoints: inputs valid, RGT looks right, cut-off sensible, blind-well results acceptable.

A secondary goal grew out of this: **RGT as a substitute for horizon autotracking**, which RokDoc lacks. That means sparse manual picks, then RGT fill-in, then snapping onto events.

**Next step (the reason for this handover):** replace the manual export/upload with RokDoc Python API reads and writes, keeping the algorithm code unchanged (see §7).

## 2. Background: RGT-Est

- Paper: Dou, Wu, Gao & Bi (2026), *Learning Stratigraphically Consistent Relative Geologic Time from 3D Seismic Data via Sinusoidal Mapping* (arXiv 2605.01273). Code MIT; data and weights CC BY 4.0 (Zenodo 10.5281/zenodo.20118902).
- Pretrained TorchScript model: `RGT-Est_CIG-Benchmark.pt` (309 MB).
- **The input grid is fixed at 400 × 512 × 512 (time, inline, crossline).** Volumes are resized to it and back. 3 input channels: normalised seismic, guidance-horizon RGT values (0 = none), guidance mask. Pad 8 with replication or reflection, crop after.
- **Guidance horizons are a soft hint, not a hard constraint.** Even fully guided, the model doesn't honour them exactly (e.g. Ranger misses by 7 ms with full guidance).
- **Memory:** a free Colab T4 (16 GB) runs out of memory. An **L4 (24 GB) works, at about 5–7 s per run**. A CPU run probably needs more than 32 GB RAM in float32; bfloat16 halves that. Not tested on CPU.
- The original repo's `train.py` doesn't run: the `Framework` class and the dataset are missing. Inference only.

## 5. Methods and data conventions (the contract the code relies on)

**Arrays:**
- **Volumes:** `numpy` float32 shaped **(inline, crossline, time)**. `samples` = TWT of each sample (ms), and `dt` in ms.
- **Seismic geometry dict `G`** (from `read_segy_cube`): `cube, ilines, xlines, samples, dt, il_idx, xl_idx` (grid index of each SEG-Y trace), `trace_index` (SEG-Y trace at each grid node, −1 if missing), `X, Y` (per node), `n_tr, il_byte, xl_byte`.
- **RGT:** 0..1, increasing downward (0 = top/youngest). Horizon = iso-surface.
- **Horizon:** `dict(name=..., t=(NI, NX) TWT map in ms, NaN where undefined)`.
- **Well:** `dict(name, il, xl, i, j, x, y, ai (resampled to seismic samples), ai_low (low-passed), valid mask, first, last)`.
- **Outputs to SEG-Y:** copy the input file and overwrite the traces (`write_like_input`), so every trace header is preserved. A decimated LFM is written with `segyio.create`, copying headers of the selected traces.

**Main workflow (`RGT-Est_OwnData_Colab.ipynb` / `local/rgt_lfm_cpu.py`):**
1. **RGT:** z-score clip (±2σ) → [−1, 1]; resize to 400 × 512 × 512 (trilinear for seismic, nearest for guidance); pad; infer; resize back; z-score clip → 0..1.
2. **Guidance volume** (authors' F3 recipe): horizon voxels dilated by 2, value = mean horizon time / NT × 2 − 1; mask = nonzero.
3. **Horizons out:** RGT iso-surfaces through chosen TWTs at the reference trace (`horizons_from_rgt` from `demo/rgt_helper.py`), exported as ASCII Inline / Crossline / X / Y / TWT.
4. **Velocity:** drop traces that are mostly outside 300–10,000 m/s; repair partial nulls; place by inline/crossline headers (or X/Y); snap near-integer positions; resample in time; linear interpolation in X/Y; nearest neighbour outside the data.
5. **LFM (multi-well):**
   - Each log is low-passed (Butterworth, `LFM_CUTOFF_HZ` = 8) on its own sampling, then resampled to the seismic.
   - **Background:** `AI ≈ a·Vint^b`, fitted on all wells (falls back to b = 1). Without velocity, a linear AI–TWT trend.
   - **Residual** (log − background) per well, mapped onto an RGT axis U (1001 bins), held constant beyond the log, with a confidence that fades over `LFM_TAPER_MS` = 100 ms.
   - Each voxel gets an inverse-distance-weighted blend (`IDW_POWER` = 2) of the wells' residuals **at its own RGT value**, scaled by the maximum confidence.
   - LFM = low-pass(background + residual).
   - **Leave-one-well-out** compares: velocity only / wells along flat time / wells along RGT (RMS %, bias, correlation).

**Horizon lab (`rgt_lab.py`):** `read_rokdoc_horizon`, `sparsify` (every Nth inline + crossline), `trace_surfaces`, `horizon_errors` (best-matching RGT level, optional mask), `flatten_section` + `continuity` (correlation of each trace with a 51-trace lateral average in a 21-level window), `dominant_frequency`, `snap_horizons` (RGT-seeded tracking: seeds where the nearest event is within 0.35 of the window, a priority-queue flood fill choosing the event nearest the neighbour's shift, majority-cycle fallback seeds, events touching the volume edge ignored, no crossings), `confidence_volume` (structure-tensor dip vs RGT-contour dip in ms/trace, linearity), `proportional_repair`.

**Classical prototype (`rgt_classic.py`):**
- `local_dips`: least-squares plane-wave slopes p, q (samples/trace) + quality (rescaled so noise ≈ 0); optional weight for normalised convolution.
- `link_coherence`: neighbour correlation along a *background* (smoothed) dip, widened by a minimum filter. `fault_aware_dips` = two passes (dips re-estimated with low-coherence samples excluded).
- `flatten`: K surfaces solved by batched preconditioned CG (DCT Poisson preconditioner) for weighted least squares on slope misfit, with Gauss-Newton re-sampling of the dips:
  - pinned at the reference trace; optional picks pinned
  - **links cut where coherence < 0.7** (`link_threshold`, hard ramp)
  - optional reference surfaces, trusted beyond `ref_scale` (≈300 traces), plus an extra pull where quality < 0.5
  - never crossing
- `reference_from_guides`: spreads the picks' offsets across the map and between picked levels.
- `surfaces_from_rgt` / `rgt_from_surfaces` convert between surfaces and RGT.
- Speed at 256 × 512 × 400 with 200 surfaces: dips + coherence about 64 s; about 26 s per outer iteration; peak about 5 GB RAM.

## 6. Results so far

**Poseidon (public, part 2):** the unguided RGT followed the reflectors well above about 1900 ms; weaker deeper and at the volume edges.

**User's crop: horizon lab run (real model, L4):**

| Version | Ranger miss | Jubilee miss |
|---|---|---|
| unguided | 9.2 ms (57% within 2 samples) | **42.3 ms** (21%) |
| guided, full horizons | 7.4 ms | 2.9 ms |
| **guided, sparse picks every 10th line** (scored on un-picked traces only) | **5.1 ms (80%)** | **3.4 ms (92%)** |

→ **Sparse picks on ~19% of traces are as good as full horizons.** This is the strongest practical result: pick on a coarse grid in RokDoc, and RGT-Est fills in.

Other lab findings:
- **The continuity metric can't separate RGT error from poor seismic continuity.** All versions scored about 0.72; the problem zone is 1600–1750 ms, below Ranger.
- **Snapping:** the jump tolerance of 4 ms (one sample) is too strict, leaving 20–55% of traces on the "kept trend". It should be automatic (max of about 1.5 samples and a quarter period).
- **Confidence is uncalibrated:** linearity is about 1 everywhere, and a tolerance of 0.25 ms/trace is far below the measurement noise (median misfit about 0.45–0.5). It needs auto-calibration from a zone where the RGT is known to be good (above Ranger), and less smoothing for 58 Hz data.
- **Proportional repair made things worse** (continuity 0.63 → 0.54). Disable it by default.
- These lab fixes are **parked** by the user's choice.

**Classical prototype:** tested on synthetics only (folds, a 12-sample fault, a chaotic zone, and a DNN stand-in with a wrong zone). Mean miss over 6 horizons:
- DNN 4.1 ms
- classical 6.2 ms (blind to fault throw)
- **hybrid 1.9 ms**
- **classical + sparse picks 1.2 ms**
- hybrid + picks 1.5 ms

The fault handling took several iterations; the hard coherence threshold was the key. **The classical-vs-DNN notebook hasn't been run on real data yet.**

**Main LFM workflow:** the multi-well LAS version has been tested only on synthetic wells. On those, blind-well RMS was: velocity only 5.7%, wells along flat time 7.0%, **wells along RGT 1.4%**. That's a best case, because the synthetic RGT was perfect. Never run with the real 4–5 wells yet.

**Lessons and pitfalls already hit:**
- An earlier notebook silently fell back to "any `.sgy`" and used a previous RGT output as the seismic. Inputs are now matched by exact name, and earlier outputs are refused.
- A cleanup command run in the wrong directory deleted a tracked file; it was restored from Git. Use absolute paths in cleanup.
- RokDoc's horizon .txt and LAS formats are as described in §4. Parsing is robust to the header lines.

## 7. Next step: RokDoc API integration (design notes)

**Principle:** add an **adapter layer** that produces exactly the objects in §5 (`G` dict, horizon dicts, well dicts, velocity on the grid), and writes results back. Then the algorithm code (`rgt_lfm.py`, `rgt_lab.py`, `rgt_classic.py`, the LFM logic) doesn't change.

**Reads needed from RokDoc:**
1. **Seismic volume** (with a sub-volume or crop option): amplitudes as an (inline, crossline, time) array, inline and crossline numbers, TWT axis (start, step), per-trace or affine X/Y. If the API only gives survey geometry, build `X, Y` from the inline/crossline → X/Y affine (the four corners are enough, see §4).
2. **Horizons:** TWT grids by inline/crossline (or X/Y), with nulls. Also support partial/sparse picks, since sparse guidance is the key workflow.
3. **Wells:** names, surface X/Y (vertical wells for now; deviated wells later need the trajectory in TWT), the **AI log in TWT using the user's well ties**, curve selection (in-situ vs `_WTR`), units, nulls.
4. **Velocity:** an interval-velocity volume in TWT. It may differ in extent or sampling from the seismic; the existing loader handles that once it's given traces + inline/crossline (or X/Y) + time axis.

**Writes back to RokDoc:**
- RGT volume(s) (guided / hybrid), LFM (full and decimated), velocity-only LFM for comparison, coherence volume (fault attribute), horizons (RGT iso-surfaces and snapped versions, TWT by inline/crossline).

**Checks worth keeping:**
- Z domain (TWT vs depth).
- Units, and the velocity type (RMS vs interval).
- Wells inside the crop.
- Horizons not crossing.
- Corner-coordinate consistency between seismic and velocity.

**Compute:** the DNN needs a GPU with about 24 GB (or a large-RAM CPU, untested). If RokDoc runs locally without a GPU, consider running RokDoc I/O locally and the model remotely, or test CPU feasibility early (`local/rgt_lfm_cpu.py` with `CPU_PRECISION = "bfloat16"`). The classical method runs fine on CPU.

**Volume size:** the model's grid is fixed. Crops bigger than about 512 traces each way need tiling. Guidance horizons can align RGT values between tiles, since each horizon has a known RGT. Not implemented yet.

## 8b. NCS seismic foundation model (added later)

- **Notebook:** `colab/RGT-Est_NCS_Embeddings_Colab.ipynb` + `colab/ncs_tools.py`. Runs `NorskRegnesentralSTI/NCS-v1-2d-base` (https://github.com/NorskRegnesentral/NCS_models, Apache-2.0; Ordoñez et al. 2025, arXiv 2603.23211) on the Norton crop with `run_inference` (densify 4 by default, about 2.5 GB). It caches the Zarr in Drive, then does PCA (32) + k-means (K = 4/6/8/12), cosine similarity to the well embedding, and a lateral embedding-similarity discontinuity map next to the classical amplitude coherence. Outputs are SEG-Y on the seismic grid.
- **Registration (checked in the NCS source, `NCS/inference/tiling.py: compute_densified_axis`):** feature coordinates are **0-based sample indices of patch centres** on the SEG-Y's sorted inline / crossline / sample axes. Patch 16, first centre 8, step 16 / densify. NCS reads geometry with segyio's default bytes 189/193. `ncs_tools.axis_maps` / `to_seismic_grid` map features onto the seismic grid: linear for continuous values, nearest for labels, constant beyond the outermost centres. In a synthetic test the mapping was exact at every feature centre.
- **Tested** only on synthetic features in NCS's exact Zarr layout (K = 4 recovered the 4 synthetic facies, ARI 1.00). **Not yet run with the real model.**
- **Planned uses with RGT:** (A) facies-aware well weighting in the LFM (similarity at the same RGT level), judged by leave-one-well-out; (B) embedding similarity as the link-cut signal in the classical/hybrid RGT, judged by the Jubilee/Ranger scores; (C) a chaos indicator for the confidence volume.
- The user also has earlier NCS work on a different dataset (1988 AVO18) with its own handover. Its open registration question is answered by the coordinate convention above.
